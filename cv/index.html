A CV that checks itself.

Every CV is a list of claims you are asked to take on trust. This one doesn't ask. As this page loads it queries GitHub and the npm registry directly from your browser and fills in the real numbers — version, publish date, last commit, repository count. Nothing below is typed in by hand.

Some claims can't be checked by a machine. Those are labelled INSPECT or NOT PUBLIC rather than dressed up as verified — which is the part I'd actually want you to notice. See also the signature verifier.

What this page does and doesn't do

The two requests are anonymous, read-only GETs to endpoints that serve already-public data — the same numbers you'd see on my GitHub and npm pages. There is no API key or token in this page, deliberately: a credential in a public page is a leaked credential, so instead of raising GitHub's anonymous rate limit I let a blocked request fail honestly and show you the endpoint.

Nothing about you is collected or sent anywhere. The one thing worth stating plainly: your browser contacts api.github.com and registry.npmjs.org, so those two services see your IP address, the same as any embedded image would.

Why build a CV like this

Because the interesting question about anyone's CV is not what it claims, it's which claims survive checking. Most of a CV can't be verified by a stranger, so the honest move is to make the checkable parts genuinely checkable and mark the rest clearly instead of letting confident formatting do the work.

That is the same instinct behind everything else I build. On a browser extension I shipped, a review pass over my own finished code found three bugs I'd already released — none of them crashed, all of them failed silently and looked fine. Code that runs is not code that is right, and a claim that reads well is not a claim that holds. You have to go and check.
